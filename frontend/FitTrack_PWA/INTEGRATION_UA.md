# FitTrack — як ОБ’ЄДНАТИ нову версію Frontend із твоїм поточним проєктом

Оновлення v2: читабельні React-компоненти, 8 тем (Graphite + Lime за замовчуванням),
згортання меню на ПК, окреме мобільне меню, приховані графіки на телефоні,
280 довідкових продуктів, створення власних продуктів, сканер штрихкодів ZXing
і додавання знайденого продукту до щоденника.

## 0. Перед початком

- Зупини старі `npm run dev` та `./gradlew bootRun` (`Ctrl+C`).
- Не змінюй Java-класи, Flyway-міграції і робочу базу `fittrack` без резервної копії.
- Збережи поточний `.env` — merge-скрипт його **не перезаписує**.
- Ніколи не копіюй архівні `node_modules` між системами. Встановлюємо через `npm install`.

## 1. Приклад розташування папок

```text
FitTrack/
├── beckend/
│   └── fittrack/           # Gradle + Spring Boot, не чіпаємо
├── fittrack-pwa/           # твій теперішній Frontend
├── FitTrack_PWA_v2_Readable/ # розпакований новий Frontend
└── start-fittrack.sh       # з'явиться після злиття
```

`beckend` — не помилка інструкції: так називалася папка у твоєму проєкті.
Скрипт запуску також розпізнає `backend/fittrack`.

## 2. Безпечне об'єднання

У **папці `FitTrack_PWA_v2_Readable`**:

```bash
# Переглянути, які файли будуть оновлені (нічого не змінює):
python3 scripts/merge_frontend.py --target ../fittrack-pwa

# Скопіювати нові файли, спершу створивши ZIP-копію старих:
python3 scripts/merge_frontend.py --target ../fittrack-pwa --apply --with-launcher
```

Якщо поточний Frontend знаходиться не поруч, передай повний шлях **у лапках**:

```bash
python3 scripts/merge_frontend.py \
  --target '/home/drack/BeackUp/University/3 Курс/FitTrack/frontend/fittrack-pwa' \
  --apply --with-launcher
```

Результат:
- Вміст нових файлів `src/`, `sql/`, `public/`, `package.json`, `vite.config.js` потрапить у стару папку.
- Скріпт НЕ видаляє сторонні файли зі старої папки.
- Старий `.env`, `node_modules`, `dist`, `.git` і lock-файли залишаються на місці.
- Стара версія збережеться в `fittrack-frontend-backups/frontend-before-v2-YYYYMMDD-HHMMSS.zip`.
- Java Backend не зміниться.
- У корені FitTrack з'явиться `start-fittrack.sh`.

Якщо Frontend ще немає, той самий скрипт створить папку `fittrack-pwa`.

## 3. Встановити залежності Frontend

```bash
cd ../fittrack-pwa
npm install
```

У `fittrack-pwa/.env`:

```env
VITE_DEMO_MODE=false
VITE_API_BASE_URL=
```

Vite Proxy автоматично передає `/api` на `http://localhost:8080`.
Якщо Backend слухає інший порт, відредагуй `vite.config.js`.
Після зміни `.env` або `vite.config.js` перезапусти `npm run dev`.

## 4. Запускати все однією командою

Повернись до **кореня `FitTrack/`**:

```bash
chmod +x start-fittrack.sh
./start-fittrack.sh
```

Скрипт запускає два процеси:
- Spring Boot: `localhost:8080` — з JDBC URL `localhost:5433/fittrack`.
- React Vite: `localhost:5173` — доступний також у локальній мережі.

Вимкнення: `Ctrl+C` у терміналі лаунчера. База PostgreSQL повинна вже працювати.
Якщо Frontend чи Backend у іншій папці, можна передати:

```bash
FITTRACK_BACKEND_DIR='/повний/шлях/backend/fittrack' \
FITTRACK_FRONTEND_DIR='/повний/шлях/fittrack-pwa' \
./start-fittrack.sh
```

Не запускати вдруге, якщо порти 8080 або 5173 уже зайняті.

## 5. Імпортувати 280 продуктів (ТІЛЬКИ один раз)

У PostgreSQL-консолі IntelliJ підключи **основну `fittrack`**, перевір:

```sql
SELECT current_database(); -- має бути fittrack
```

Відкрий файл `fittrack-pwa/sql/seed_280_products.sql`, виконай **весь SQL**.
Продукти будуть публічними (`owner_id IS NULL`); повторний запуск
не дублює ті ж назви. Вони НЕ мають вигаданих штрихкодів.
Калорійність і БЖВ довідкові/орієнтовні — для магазинних упаковок
потрібно вводити дані з етикетки.

Перевір:

```sql
SELECT COUNT(*) FROM products WHERE owner_id IS NULL;
```

Загальна кількість публічних продуктів може бути БІЛЬШОЮ за 280,
якщо в тебе вже були продукти в БД.

## 6. Робота зі штрихкодами

1. Каталог → **Сканувати** або Харчування → **Сканувати**.
2. Наведи камеру на реальний EAN / UPC; або введи цифри вручну.
3. Якщо код збережено в твоєму Backend — відобразиться знайдений продукт.
4. Якщо код невідомий — заповни назву та БЖВ на 100 г з етикетки, збережи.
5. Вибери грамовку та прийом їжі → **Додати в щоденник**.

**На телефоні камера потребує HTTPS** (або захищеного localhost).
Адреса типу `http://192.168.1.x:5173` підходить для перегляду PWA
і ручного введення коду, але зазвичай НЕ дає доступу до камери.
Для реального сканування на телефоні налаштуй локальний HTTPS
або опублікуй тестовий Frontend за HTTPS. Дозволь браузеру доступ до камери.

## 7. Якщо цілі / підрахунки повертають 404

Це може означати відсутність налаштованої цілі у нового користувача,
або справжню відсутність маршруту контролера.
Спробуй спочатку створити ціль у розділі "Мої цілі".
Якщо `PUT /api/v1/goals/me` повертає 404, звір `@RequestMapping` Java-контролера
та `src/lib/api.js`. Сторінка відтепер показує конкретні помилки завантаження.

## 8. Як відновити попередню версію

Зупини Vite та Backend. Розпакуй резервну ZIP-копію зі
`fittrack-frontend-backups/` назад у `fittrack-pwa` з перевіркою конфліктів.
Нові файли, яких не було у старій версії, можуть залишитися — при потребі
видаляй їх вручну після звірки списку файлів.

## 9. Перевірка перед демонстрацією викладачу

```bash
npm run build
```

Після запуску перевір через браузер: Login → Каталог → Створити продукт →
Штрихкод → Записати в щоденник → Аналітика → Мої цілі → 8 тем →
Згорнути/розгорнути меню → Розмір мобільного екрана (графіків немає).

**Важливо:** оскільки точні DTO/ендпойнти Backend можуть відрізнятися від
наданих у чаті, перевір живі API у `src/lib/api.js`. Архів не включає Java Backend.
